SHOPGRAPH — CATEGORY MANAGER BROAD CATEGORY COMPLETION
=======================================================

TASK
----

Analyze the attached ShopGraph exports:

    shopgraph_category_manager.txt
    shopgraph_purchase_history.txt

Your job is to complete ONLY missing broad Category assignments in the
Category Manager export.

ShopGraph taxonomy:

    Common Name
        ↓
    Sub-Category
        ↓
    Category

The Category Manager contains:

    Category
    Sub-Category
    Product 1
    Product 2
    Product 3
    ...

The Purchase History contains the underlying product history and includes:

    Store
    Six-Digit SKU
    Product
    Common Name
    Sub-Category
    purchase dates/prices

The only target rows are Category Manager rows whose:

    Category = NA

Existing non-NA Category assignments are authoritative taxonomy reference data.

Do NOT modify or recommend changes to any existing non-NA Category assignment.


=======================================================
CORE RULE
=======================================================

    EXISTING CATEGORY ASSIGNMENTS TEACH THE BROAD TAXONOMY.
    NA CATEGORY ASSIGNMENTS ARE THE ITEMS TO CLASSIFY.


=======================================================
WHAT MAY BE CHANGED
=======================================================

ONLY determine the broad Category for Category Manager rows where:

    Category = NA

Do NOT:

    rename Common Names
    rename Products
    rename Sub-Categories
    move Products between Sub-Categories
    alter Purchase History
    change non-NA Category assignments
    create another taxonomy level
    rewrite Category Manager
    return a replacement CSV


=======================================================
HOW TO LEARN THE EXISTING CATEGORY TAXONOMY
=======================================================

First study every existing non-NA:

    Sub-Category → Category

relationship in shopgraph_category_manager.txt.

Those assignments are authoritative evidence of ShopGraph's intended broad
taxonomy and naming style.

Build an internal reference map such as:

    existing Sub-Category
        → existing broad Category

Do not "clean up," rename, merge, normalize, or reorganize those historical
assignments.

When an NA Sub-Category clearly belongs to an existing Category, reuse the
existing Category exactly as written.


=======================================================
USE CATEGORY MANAGER PRODUCT EVIDENCE
=======================================================

For each Category = NA row, study:

    Sub-Category
    Product 1
    Product 2
    Product 3
    ...

These Products/Common Names show what the Sub-Category actually contains.

Analyze all products on the row together rather than relying only on the
Sub-Category wording.


=======================================================
USE PURCHASE HISTORY AS SUPPORTING EVIDENCE
=======================================================

Use shopgraph_purchase_history.txt to understand ambiguous or unfamiliar
Sub-Categories.

Find Purchase History rows whose:

    Sub-Category

matches the NA Category Manager row.

Then study relevant:

    Store
    Six-Digit SKU
    Product
    Common Name
    Sub-Category

data.

Purchase History is supporting product evidence.

Existing non-NA Category Manager assignments remain the authority for the
broad taxonomy.


=======================================================
CLASSIFICATION PRIORITY
=======================================================

For every Category = NA row:

1. Identify what the Sub-Category represents from its name and associated
   Products/Common Names.

2. Check existing non-NA Sub-Category → Category relationships for closely
   related product types.

3. Use Purchase History product records when additional context is useful.

4. Prefer an EXISTING broad Category when it genuinely represents the
   Sub-Category.

5. Reuse the exact established Category spelling/capitalization.

6. Avoid creating near-duplicate Categories that differ only by wording,
   capitalization, singular/plural, or minor phrasing.

7. Do NOT force an item into an existing Category merely because it is the
   closest available label.

8. Create a NEW broad Category only when the Sub-Category belongs to a
   materially different purchasing domain not adequately represented by the
   established taxonomy.

9. Apply the same reasoning consistently to related NA Sub-Categories.


=======================================================
NEW BROAD CATEGORIES
=======================================================

ShopGraph may contain purchases from many domains, including groceries,
household goods, baby products, personal care, pets, automotive, tools,
electronics, office supplies, garden, furniture, clothing, services, and
others.

Do not assume every new Sub-Category belongs to Food.

A new Category may be created when necessary.

A new broad Category should:

    be concise
    be human-readable
    represent a broad purchasing domain
    be broader than a Sub-Category
    be useful for future comparable Sub-Categories
    match the naming style of existing Categories
    not describe a retailer
    not simply repeat a highly specific Sub-Category unless that genuinely
        represents the broader domain

Create new Categories conservatively.


=======================================================
UNCERTAINTY
=======================================================

Make the best evidence-based classification when reasonable.

Use:

    NA

only when the Category Manager and Purchase History evidence is genuinely
insufficient to determine a reasonable broad Category.

Do not fabricate unsupported details merely to avoid NA.

Do not use NA simply because ordinary semantic inference is required.


=======================================================
CONSISTENCY CHECKS
=======================================================

Before producing the answer:

1. Verify that every target row really has Category = NA.

2. Verify that no non-NA Category Manager row is included as a target.

3. Check whether the proposed Category already exists.

4. Prefer an existing Category over a synonymous new one.

5. Check associated Products/Common Names.

6. Check Purchase History evidence when useful.

7. Apply consistent Categories to related Sub-Categories.

8. Confirm that every target row appears exactly once in the output.

Return TWO sections only.

|---:|---|---|---|

When useful, state whether the classification:

    follows an existing Category precedent

    creates a genuinely new broad Category
