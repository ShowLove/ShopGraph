ShopGraph - Component Consensus OCR Update

PURPOSE

This update changes only:

    utils/compare_ocr.py

The previous version chose one complete OCR line for each consensus line.

This version keeps the same six-candidate pipeline but changes product-line
assembly.

For a line containing exactly one six-digit SKU, the program now treats these
as independent components:

    SKU
    description
    price
    tax code

Example OCR evidence:

    356537 Cilantro
    356537 Cilantro
    356537 Cilantro 0.89 FA
    356537 Cilantro 0.89 FA

The program can reconstruct:

    356537 Cilantro 0.89 FA

without inventing a product name or price.

RULES

- Exact six-digit SKU is the alignment key.
- Description remains OCR-derived.
- Price must appear in an OCR candidate.
- Tax code must appear in an OCR candidate.
- No product dictionary is used.
- No spelling correction is performed.
- Near-SKU values such as 256578 vs 356578 are NOT merged yet.

INSTALL

Replace:

    utils/compare_ocr.py

No other file needs to change.

RUN

    python3 main.py

Then:

    1. Utilities
    6. Compare OCR Results / Build Raw OCR JSON

The smart pipeline still runs all missing earlier stages automatically.

EXPECTED TERMINAL OUTPUT

    === Compare OCR Results / Build Component Consensus ===

    [OK] Component consensus OCR built from all candidates.

    Backbone candidate:
    Variant: grayscale
    PSM: 4
    Score: ...

    Consensus:
    Lines: ...
    Product lines reconstructed: ...
    Supported extra lines: ...

OUTPUT

    data/raw_ocr/<receipt>_raw_ocr.json

New useful fields on reconstructed product lines:

    reconstructed
    original_consensus_text
    reconstruction_method
    component_support

This makes it possible to inspect exactly which OCR evidence supplied the
description, price, and tax code.
